## 范围与实现顺序

1. **客户、商品、采购库存**：客户与通信账号分离，查询快照及绑定历史；客户全景和到期跟进；实物商品的数量/序列号管理；供应商、采购审批、实际收货、库存流水。验证上一版本迁移、部分/重复收货、权限、库存与序列号约束。
2. **销售、收银、通信、安装与收益**：后端按已发布版本计算订单和优惠，人工确认，独立 Mock 模拟支付，原请求号核对，幂等出库；日结；成功受理更新客户业务台账；预约派工、领料、安装验收；版本化收益与提成规则、模拟账单对账。验证金额、并发、重复操作及一条完整正常业务链。
3. **经营与演示交付**：带口径和来源的看板；销售草稿与经营摘要复用现有受控 AI；人工录入/导入 GEO 回答；补演示数据、页面和操作说明。验证授权页面、离线 AI 降级及相关前端构建；只在需要时执行少量真实模型试跑。

## 具体业务约定

- 单店正常流程，全部经营数据及收款为模拟；不调用真实支付。三期再做退款退货、跨店调拨、跨期追扣和复杂异常补偿。
- 沿用门店和客户 ID。销售单显式关联 source_service_id / source_acceptance_id，不修改推荐记录承担订单职责。
- 实物售价和安装费复用不可变政策版本的一次费；套餐月费仅展示，不擅自计入收银实收。优惠使用已发布政策中的明确固定折扣，不接受前端传入最终金额。
- 钱、库存、外部受理、安装状态分别记录。提交外部请求前持久化请求号，网络调用期间释放数据库锁；超时保留 UNKNOWN，核对原请求。
- 正常收货和出库使用数据库短事务与约束；演示吞吐下按商品锁行。所有库存变化留来源、数量、经手人与时间。
- 增加实际需要的仓库、装维和财务账号；后端限制动作和门店，装维仅看分配给自己的工单。发布政策仍由管理员完成。
- 收益、代收、押金和实际现金分别统计；预估收益、已收收益、待结算提成不混用。规则和单据快照保留版本。
- 客户、外部 AI 回答、模型输出均按不可信数据处理。AI 只能生成草稿或引用允许的统计证据，不获得定价、权限、任意 SQL 和业务提交能力。
- 不新增基础设施或通用单据引擎，不改动原 Word 文档的历史决策。每个施工包记录实际结果与迁移，不以计划代替完成。

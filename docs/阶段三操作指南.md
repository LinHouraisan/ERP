# 第三阶段操作与演示指南

打开 [统一待办](http://127.0.0.1:5173/todos)。一店用 `admin`，二店用 `admin2`；对应店员、仓库、装维、财务为 `staff`、`warehouse`、`installer`、`finance`，二店名称加 `2`。口令沿用私有 `.env`，所有业务均为模拟。

## 推荐演示顺序

1. **组合交易**：打开“两台路由器交付后退一台”，原金额 558.00、已退 279.00、净收 279.00；点子单可查看原收款和退货。另一个“设备已交付，现场安装受阻”仍显示异常，销售完成不会掩盖施工未完成。
2. **售后退款**：查看“退回一台路由器”和“未交付全额取消”。前者按原序列号入库，后者只释放预留。第三条“模拟退款成功但返回超时”可点“按原退款号核对”，再记录依据结案。
3. **通信冲正**：查看套餐撤回样本。原成功受理保留，另有冲正成功回执；重新查询 `19900000014` 可看到恢复后的 129.00 元。旧单缺少办理前快照时按页面要求人工核查。
4. **结算与差异**：查看 `staff` 两笔分期结算和后续抵扣；最后一笔明细为 -5.58 和 +20.98，净发 15.40。下方有一笔待审批的 2.00 元补发申请。
5. **调拨盘点**：查看全部收齐、短到待查、核损结案三种样本。退出后用 `warehouse2` 或 `admin2` 登录，从调入方验收；一店负责核查剩余在途。重复提交不会再次增加已收数量。
6. **统一待办**：筛选全部、分配给我或逾期，从“打开原单”继续处理。装维只看到自己的任务，二店不能读取一店客户和财务。

操作会修改本地模拟单据，样本状态自然变化，不自动还原历史。不要删除进度文件重复造单。

## 处理规则

从销售原单申请售后，选择行、金额和退货数量；店长审批，仓库验收，财务退款，两项核实后结案。修改内容需新申请，原审批和外部请求不可覆盖。退款未知只核对原号。

明确失败后不能继续验收入库。未退库时，店长写明客户继续交付或后续安排，可结束失败申请；已退库时，先建仅退款的后续单并成功结案，再回到失败单关联该退款、记录依据。原失败结果保留，不能用此入口关闭未知结果。

施工受阻后可改约，原领料保留，重新派工说明保管交接；复访不再重复扣库存。取消时记录实际退回的额外耗材和设备，未退回部分说明原因；销售设备退款仍走原销售售后。

账单填写业务归属期、结算期、行标识及是否最后一期，到账未知留空。收益补发扣回须店长批准，提成按原规则。结算选员工和正向来源，后台先抵扣该员工历史负余额，余额不足则拒绝。

盘点保存当时账面与实盘，审批前库存变化必须重盘，客户预留不能被抹除。调拨只允许同主体、相同商品编码及追踪方式；一单一个商品，可分次验收。

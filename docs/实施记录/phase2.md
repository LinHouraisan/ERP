## 接口、状态与数据归属

保留模块化单体和独立 HTTP Mock，不新增依赖或基础设施。新增 `accounts/router.py`、`inventory`、`sales`、`installations`、`finance`、`operations` 模块及对应前端页面；模型调用仍集中在 `integrations/ai.py`。

| 接口前缀（均在 /api/v1 下） | 数据与约束 |
| --- | --- |
| customers | 客户与账号分离；查询形成绑定历史；已成功通信受理写入不可变客户业务台账；到期任务关联来源快照 |
| inventory | 供应商、采购审批、实际收货、序列号、库存与流水；短事务行锁，重复收货不重复入库 |
| sales | 政策版本生成订单行，后端优惠与金额；订单确认、收款和出库独立；日结分列经营款/代收/押金及支付方式，并能查看原订单 |
| installations | 订单或受理二选一为来源；预约、派工、接单、领料、到场、安装、客户验收；装维仅处理自己的工单；领料前支持改约退回待派 |
| finance | 版本化规则、冻结收益计算、原始账单和匹配；预估、应结、实际到账分开，缺失为未知；按冻结规则判断提成可结算条件 |
| operations | 授权统计快照与 AI 摘要；GEO 保存原始回答、平台、时间、引用、人工事实核查，真实与模拟分别计数 |

Mock 增加持久化模拟付款与账单接口。付款先保存请求号和库存占用，再释放事务调用 HTTP；超时保存 UNKNOWN，查询和重试沿用原请求号。终态不能被迟到结果覆盖。销售出库和安装额外领料分别留库存来源；已售设备在安装交接时不重复扣库存。

AI 新增 sales、operations 两类版本化提示词和可审计运行。销售只输出候选政策和数量草稿，人工采纳后重新核价；经营摘要的数字和引用 ID 必须与服务端快照一致。模型没有改账、定价或任意查询能力。解释文字仍需人工核实，联网成功不等于质量评测通过。

## 保留的边界

当前是单店本机模拟业务，未连接真实运营商、支付和资金发放。复杂退款退货、组合交易部分失败、跨期冲回、跨店协作按规划留在第三阶段。列表有 100/300 条上限，当前数据量已覆盖；需要更长历史时再扩展分页。

一期正式人工标签核对与 V1/V2 质量比较、Docker 引擎运行、第二台干净机器安装仍未验证。没有以模拟经营数字或联网成功声称经营收益、准确率或效果提升。

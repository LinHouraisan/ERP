# 阶段一约十分钟演示脚本

准备：按 [README](../README.md) 启动本机版，登录 `admin`；另开 `/take-number` 和 `/public-board`。当前本机横幅为模拟数据、DeepSeek 辅助已启用，点击 AI 按钮会使用真实额度；切换 offline 可演示固定输出。已有完成数据可从 [演示数据记录](实施记录/phase1-demo-data.md) 直接查看，不必重跑付费调用。

| 时间 | 操作 | 观察点 |
| --- | --- | --- |
| 0—1 分钟 | 在客户页选套餐业务取号；工作台 1 号窗口叫号并开始接待 | 公共屏字段有限；接待关联同一票号，重复叫号不会抢新票 |
| 1—2 分钟 | 查询本机尚未变更的 `19900000003` | 套餐、宽带、费用、来源及两种时间；不是模型编造的事实 |
| 2—4 分钟 | 填降低费用、保留宽带，生成建议；选择符合条件的 89 元方案 | 月费差额 40.00、新合约 12 个月、一次费与政策版本；79 元不保宽带不入选；未知费用不当作零 |
| 4—5 分钟 | 质检，查看依据，写复核原因；创建草稿并确认提交 | 状态从草稿到外部结果，保存唯一请求号与外部单号 |
| 5—6 分钟 | 再次查询账号，展开历史快照；结束接待 | 当前变为 89 元，旧 129 元快照仍在；结束接待不会把未知受理改成成功 |
| 6—7 分钟 | 生成评价链接，客户选分并填写意见；回工作台刷新评价 | 本次服务关联真实提交的模拟评价，不给未评价服务补分 |
| 7—8 分钟 | 打开文本质检，选融合89的 V1 政策；输入“月费59元，合约12个月。” | 错价阻断，有依据；修订为“月费89元，合约12个月。”后生成新检查，原文仍可查 |
| 8—10 分钟 | 统计与改进查看样本及比例；生成草稿、审核、开始处理，生成新快照，填写验证条件与“样本不足，不认定效果”，验证后关闭 | 有证据才审核、有验证才关闭；查看真实模型运行与20条联网试跑，说明正式效果评分待标签核对 |

89 元演示要求号码当时仍为 129 元且政策有效；重复办理后如有新合约会提示核查在约限制，不能直接当成无条件变更。初始化不会覆盖已办理事实。目前 01、07、11 已办理为 89 元；03 保留原套餐，可用于新的正常流程。当前有一笔 UNKNOWN 演示单，需先核对再考虑 README 中的受限重置。

## 三个可复现自动情景

根目录先执行 `.\.venv\Scripts\python.exe scripts/prepare_tests.py`，再在 frontend 运行对应命令。夹具创建新的测试模拟账号，独立于演示账号；端口与环境要求见 README。

| 命令 | 情景与结束点 |
| --- | --- |
| `npm run e2e -- service-flow.spec.ts` | 取号 → 接待 → 查询 → 推荐 → 复核 → Mock 成功 → 结束 → 评价 → 后台关联记录 |
| `npm run e2e -- ai-fallback.spec.ts` | DeepSeek 模式故意不给密钥，真实记录 AI 失败；继续人工需求、规则方案、质检复核和办理 |
| `npm run e2e -- unknown-result.spec.ts` | Mock 保存成功后延迟响应；页面先未知，刷新后按原号核对成功，应用记录和外部单号不重复 |
| `npm run e2e -- admin-pages.spec.ts` | 建议审核、处理、验证关闭；读取管理页；文本错价阻断、修订后保留两版 |

额外人工检查：号码 04 展示未知月费；02 展示在约限制；12 区分查询超时和“号码未找到”；新建故障服务可留下处理任务。业务边界按当天 Asia/Shanghai 日期计算，03 的固定合约日期只适合解释边界，不把它永久称作“今天到期”。

展示备份恢复时打开 [施工记录](实施记录/phase1.md) 中的实际备份、恢复库和原请求号证据。不要通过删未知单、更换请求号或硬改状态演示“恢复成功”。
